# Event Gate design

Standing description of coded behavior in xfighterjock/broker.

Product/UI name is Event Gate; package name is broker. Trader: Richard. Product clock: America/New_York (TZ).

If this file disagrees with code, the code wins. Update this file and docs/ABBREVIATIONS.md whenever design, sleeve methodology, tickers, or abbreviations change.

## What it is

Paper risk-gate plus briefing dashboard. Five independent mock $100k sleeves. BUY/SELL fills are MockBroker only (delayed last + hard stop). No live or demo Tradovate orders. TRADING_MODE=live is refused. E*TRADE is quotes, chains, and OAuth only — never orders.

## Runtime

- Client: Vite + React SPA (client/). Desktop layout; phones (narrow viewport or /m) get essentials (clock, cash open/close countdown, US cash closed/holiday strip, GATE, RISK, AUTO PAPER + D/M/O/Ow/Cs chips, read-only `knowledgeTime` and Stage-3 (`Stage-3 armed (auto)` / `Stage-3 not armed`), Flatten, sleeve P/L). The desktop freeze panel shows the same read-only `knowledgeTime` and Stage-3 line. There is no Stamp knowledge time button on desktop or `/m`. Native iOS Event Gate (ios/, bundle com.logikmancer.mybroker) is the phone Event Gate client: same essentials plus FCM, a paged Activity screen, and an E*TRADE re-auth banner when `etradeAuth` is not `ok`. iOS shows current `knowledgeTime` and whether Stage-3 is armed (`Stage-3 armed (auto)` / `Stage-3 not armed`) from snapshot `stage3Armed` (it does not decode the calendar) and does not stamp. Web recomputes the same print-day rule from `events`. Web /m remains for browsers. No WKWebView wrapper. Cold start paints login or last-session essentials immediately from Keychain + a cached GET `/api/status` snapshot — it does not wait on Firebase/FCM or a live status call. `FirebaseApp.configure()`, APNs, and FCM attach run after the first frame (`AppDelegate.startFirebaseAfterFirstFrame`). While unlocked, iOS polls GET `/api/status` every 3 seconds (`StatusController.pollInterval`) in the background. BrokerAPI uses `URLSession.shared` (the system session Safari shares) with a 10s `URLRequest` timeout. Do not switch to an ephemeral session — that session does not use the system connection path. `waitsForConnectivity` stays at the shared-session default (false); do not create a custom session just to set it. Transport errors include the absolute URL that was requested (built with `URLComponents` from the stored base URL + path) so a timeout shows the host the app actually called. First paint must not wait on that request. A swipe-kill is a new process, not a leftover socket. That snapshot does not wait on delayed-quote paper marks (see Paper engine). Activity history is not on that snapshot — the phone loads GET `/api/activity` when the Activity screen opens (newest page first, older pages on scroll) and must not block first paint.
- Server: Node 24 Express (server/), bind 127.0.0.1:3001.
- Shared: clock, market session (NYSE holiday calendar), constants, types (shared/).
- Store: Postgres (events, freeze snapshots, users + user_sessions, iOS FCM tokens, alert dedupe, gate_log + session_logs with 90-day retention) + Redis (gate, sleeves, blotter, mock book, session marks, scan cache, per-sleeve AUTO PAPER, SPA cookie sessions, last-known RISK ON/OFF at `risk:on`).
- Front door: nginx TLS at broker.logikmancer.com. Production AUTH_MODE=users (users table + cookie eg.sid and/or opaque bearer). Local default is cookie + GATE_PASSWORD. AUTH_MODE=nginx is remapped to users in production — htpasswd is no longer the app login (deploy/nginx/event-gate.conf has no auth_basic). GET /api/public/risk stays unauthenticated: nginx does not require a session and Express exempts that exact path. It returns only {riskOn, riskChecks, asOf} (no-store) — never P/L, orders, positions, auth state, or secrets. GET /api/status and notification endpoints stay behind app auth. Optional EVENT_GATE_OPS_TOKEN (VPS `.env`, never git) accepts `Authorization: Bearer` over public HTTPS for a narrow ops scope: GET /api/status, GET/PUT /api/freeze, GET /api/health, GET /api/sleeves, POST /api/paper/auto, POST /api/flatten, POST /api/paper/reset, POST /api/gate/enable, POST /api/knowledge-time, POST /api/etrade/renew. Print-day vetoes are flatten sleeve and GATE OFF (`{ enabled: false }`). Sleeve reset (POST `/api/paper/reset` `{ sleeveId }`) wipes one mock book without a delayed last. Knowledge-time stamp is the same as a user POST (memory + freeze row + checklist `knowledgeTimeAfterPrint`; idempotent if already stamped that ET day). The GATE route is a single toggle — `{ enabled: true }` or omitted `enabled` (defaults ON) also GATE ON; there is no separate disable path. POST `/api/etrade/renew` force-renews the E*TRADE access token (GET oauth/renew_access_token idle-expiry reset only; midnight ET still needs a human PIN). Not a full admin session — paper orders, E*TRADE PIN (`/api/etrade/oauth/start` and `/pin`), mock inject, cancel-stops, and user admin stay 401. When unset, behavior unchanged. Agents can freeze-save, status-check, toggle AUTO, flatten, reset a paper sleeve, GATE OFF, stamp knowledge_time, and force-renew the E*TRADE access token without Richard's Mac or SSH to 127.0.0.1:3001.
- Unit: systemd event-gate on the VPS (WorkingDirectory `/opt/broker`, `ExecStart` `node dist/server.js`). Deploy source is GitHub Actions (GHA) on every push to `master` and on `workflow_dispatch` (docs/DEPLOY.md). CI (`npm test`, `npm run typecheck:server`, `npm run typecheck:client`) runs first; the VPS sync runs only if CI passes. The runner rsyncs `dist/server.js`, `dist/server.js.map`, and `dist/package.json` to `/opt/broker/dist/` (no `--delete`) and `rsync -a` of `client/dist/` to `/opt/broker/client/dist/`. Before restart it rsyncs `db/migrations/*.sql` only to `/opt/broker/db/migrations/` (`--no-owner --no-group --chmod=F644,D755`, no `--delete`, so SQL already on the box is kept) and fails unless `ls` on the VPS shows every local migration filename. Then `systemctl restart event-gate`. The job fails unless `systemctl is-active event-gate` is `active` and the remote md5 of `/opt/broker/dist/server.js` matches the build. Host, user, SSH key, known_hosts, and optional port are repository secrets (`DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`, `DEPLOY_PORT`), never committed. If `DEPLOY_SSH_KEY` is unset the deploy step skips with a notice and stays green. A weekday 09:30–16:00 America/New_York deploy still runs and logs a warning. `dist/migrate.js` is not copied. Boot applies the SQL in `/opt/broker/db/migrations` (the files just rsynced). A Mac checkout rsync (`deploy/gha-sync.sh`) remains the fallback. Concurrency group `event-gate-vps-deploy` queues a second deploy instead of overlapping it.
- No Docker. Production needs postgres, redis, AUTH_MODE=users, a cookie-signing secret (SESSION_SECRET, or GATE_PASSWORD as fallback), and at least one row in `users`. GATE_PASSWORD is not the users-table login and is not GATE ON/OFF (that is POST /api/gate/enable).
- Push notifications: FCM is fail-closed until `PUSH_FCM_ENABLED=1` plus Firebase Admin credentials on the VPS. The iOS app registers/revokes tokens (Bearer session, still `x-remote-user: event-gate`) and can request a test push. The real `GoogleService-Info.plist` (API_KEY) is not in git.

## Activity log

The existing journal is `gate_log` (`engine.log` / former `actionLog`). Do not invent a second write path. It already records GATE enable/disable and tick cancels/flattens, paper fills/closes, sleeve resets, AUTO PAPER toggles and autopilot lines (including overlay rotate and credit-put open/stop). `session_logs` still receives `sessionNote` rows (freeze/checklist) but is not the phone feed.

GET `/api/status` returns empty `actionLog` and `sessionLog` arrays. Status must not ship log history — the iOS poll already timed out around ~57KB.

GET `/api/activity?limit=&before=` is the paged read (requireAuth, not ops-token). Newest first. `limit` defaults to 50, max 100. `before` is a `gate_log.id` cursor (rows with id strictly less than that). Response `{ entries: [{ id, ts, message }], nextBefore, hasMore }`. GET `/api/log` is the same page plus a `log` alias of `entries`. Without postgres, pages in-process `engine.getLogs()` with synthetic ids. Desktop `[EventGate] log` loads the first page of `/api/activity` (not the status snapshot).

Retention: `ACTIVITY_LOG_RETENTION_DAYS` = 90. `purgeExpiredLogs` deletes `gate_log` and `session_logs` rows with `ts` older than 90 days. Runs at process start and every 6 hours. Migration `004_activity_retention.sql` indexes `ts` on both tables.

## Users and login

Postgres `users` (username unique, argon2id `password_hash`, optional `disabled_at`) and `user_sessions` (sha256 of an opaque bearer, 30-day expiry). Migration `003_users.sql`.

Two session stores after a users-table login (`server/src/auth.ts`, `server/src/users.ts`):

- SPA cookie `eg.sid` lives in Redis (`eg:sess:` prefix via connect-redis). Cookie `maxAge` is 7 days (`7 * 24 * 3600 * 1000` in `buildSessionMiddleware`). Cookie name and Redis prefix differ on purpose.
- iOS opaque bearer lives in Postgres `user_sessions` (sha256 of the token). `SESSION_TTL_MS` is 30 days.

- POST `/api/auth/login` `{ username, password }` (AUTH_MODE=users) sets cookie `eg.sid` and returns `{ ok, username, token, expiresAt }`. SPA uses the cookie; iOS stores the bearer in the Keychain and sends `Authorization: Bearer`.
- POST `/api/auth/logout` destroys the cookie and revokes the presented bearer.
- GET `/api/auth/status` returns `{ authRequired, authed, mode, username }`.
- AUTH_MODE=cookie still accepts the shared GATE_PASSWORD (local / tests). That path is not production.
- Optional EVENT_GATE_OPS_TOKEN: long-lived HTTPS ops bearer compared constant-time (`tokensEqual`). When it matches, auth attaches `eventGateUser` `{ id: 0, username: "ops-token" }` and `eventGateOps=true`. Fail-closed allowlist in `requireOpsScope` (status, freeze, health, sleeves, POST /api/paper/auto, POST /api/flatten, POST /api/paper/reset, POST /api/gate/enable, POST /api/knowledge-time, POST /api/etrade/renew). POST `/api/etrade/renew` only resets idle expiry via GET oauth/renew_access_token; midnight ET still needs a human PIN (`/api/etrade/oauth/start` and `/pin` stay user-session only). Other mutating routes stay 401. Cookie `eg.sid` and users-table bearer sessions keep full access. Never commit or paste the token.
- First user: set `BOOTSTRAP_ADMIN_USER` / `BOOTSTRAP_ADMIN_PASSWORD` in the VPS `.env` (gitignored) and restart once while `users` is empty — then unset those vars. Or `npm run user:create -- <username>` (password from stdin or `EVENTGATE_NEW_USER_PASSWORD`). Never commit passwords.
- Auth rules (`server/src/users.ts`): usernames are stored lowercase and must match `^[a-z0-9._-]{2,32}$` at create. Passwords are 8–200 characters at create. Failed POST `/api/auth/login` attempts are rate-limited per username (`LOGIN_MAX_FAILURES` = 8 in `LOGIN_WINDOW_MS` = 15 minutes; in-process map).
- iOS: Face ID / Touch ID (LocalAuthentication) only unlocks a Keychain session already issued by login. Settings can disable biometrics. Failure falls back to username/password.

## Event clock and GATE

Binds the day sleeve only. Does not flatten momentum, options, ownership, or risk-off. One-second tick when GATE is enabled (server/src/gate.ts, shared/clock.ts).

| Mode | Window | Action on gated roots |
| --- | --- | --- |
| idle | otherwise | none |
| PRE-ARM | T-15m to T-2m (PRE_ARM_MS) | cancel Market / StopMarket / StopLimit / MIT |
| NO-STOP BAND | T-2m to T+2m (BAND_MS) | same cancels |
| SESSION FLATTEN | flatten ET +/- 5m (FLATTEN_WINDOW_MS) | flatten gated names; also daily loss |

- Gated roots (GATED_ROOTS): MES, MNQ, ES, NQ, ZN, ZF, ZT, ZB, SR3, 6E, M6E. Qty over MAX_QTY (1) is cancelled. Limits left alone unless oversize.
- Daily loss cap default $500 (DEFAULT_DAILY_LOSS_USD). Day-sleeve paper entries use that sleeve's realized P/L, not broker-wide mock:day_pnl (other sleeves must not block MES). GATE flatten-on-daily-loss still reads MockBroker.getDayPnl() (realized accumulator + open unrealized). That accumulator does not roll with NY session marks and can drift from sleeve cards. POST `/api/paper/reset` rebuilds it from remaining sleeves' session dailyPnlUsd (does not wipe another sleeve's today). POST `/api/day-pnl` is the manual ops path. FOMC in the event type forces 15:30 ET flatten; NFP/CPI seed flatten 15:45 ET. The day-sleeve `cpiLateFade` MES lot is exempt from that 15:45 session flatten (it flattens at the cash close). Daily-loss flatten, oversize qty, and manual Flatten still include it.
- Freeze card (NFP/CPI/FOMC): consensus objects, source, FedWatch, liquid contracts MES/ZN/M6E/SR3. Print-day veto is Flatten or GATE OFF. Freeze auto-save must never flatten or place directional orders.
- knowledge_time: POST `/api/knowledge-time` remains a backstop (user session or EVENT_GATE_OPS_TOKEN). It sets memory.knowledgeTime, stamps the latest freeze row, and marks checklist `knowledgeTimeAfterPrint` when that field exists only when the America/New_York day has an NFP, CPI, or FOMC row and `now` is at or after that day's anchor print. A non-print day (jobless claims, a blank day) or a stamp before the print is refused with HTTP 409 and is not stored. The log line is `knowledge_time refused (manual|ops): knowledge_time not on a print day` or `knowledge_time before print`. A stamp already at or after the anchor that ET day is idempotent — no second write. A leftover stamp from before the anchor does not count, so auto-stamp can still write at the print. Desktop, web `/m`, and iOS do not call it; they only display the stamp and Stage-3. Logs also distinguish `knowledge_time manual`, `knowledge_time ops-stamped`, and `knowledge_time auto-stamped`.
- Auto-stamp: on an NFP, CPI, or FOMC America/New_York day, at or after the anchor print time, if knowledge_time is still unset for that ET day (or the only stamp is from before the anchor), the status snapshot (`maybeAutoStampKnowledgeTime` in `snapshot`) and the autopilot tick (`runWiredAutopilot`) auto-stamp whether or not a freeze card exists. FOMC uses STATEMENT when both STATEMENT and PC exist; otherwise the FOMC row. NFP and CPI use the print time. Jobless claims and other non-print rows do not stamp (`isPrintEvent` is still NFP, CPI, and FOMC only). A stamp already at or after the anchor that ET day → no re-stamp. Does not weaken idle-RTH, PRE-ARM, NO-STOP BAND, or SESSION FLATTEN MES vetoes.
- Calendar: production loads `events` from Postgres (`loadEvents` in `server/src/index.ts`) and, when that table has any rows, uses those rows instead of `seedEvents()`. The no-Postgres fallback is `shared/clock.ts` `seedEvents()`. Migration `001_init.sql` inserted only September 2026 (NFP Sep 4, CPI Sep 11, FOMC statement + press conference Sep 16). No later migration appended rows, so after those prints `clock.nextEvent` stayed null, mode stayed idle, auto-stamp had nothing to fire on, and the 15:45 / 15:30 flatten clock had nothing to protect. Migration `005_calendar_through_2027.sql` inserts the verified NFP, CPI, and FOMC statement + press conference rows from October 2026 through December 2027 (`ON CONFLICT DO NOTHING`). NFP and CPI are 08:30 America/New_York from the BLS Employment Situation and CPI schedules; 2027 day-of-month dates also match the OMB Principal Federal Economic Indicators schedule (whitehouse.gov `FY2027-PFEI.pdf`). FOMC statement is 14:00 ET and the press conference 14:30 ET on the second meeting day, from federalreserve.gov/monetarypolicy/fomccalendars.htm and the September 5, 2025 schedule release. January 2028 prints are not on those schedules and are not seeded. `calendarStale` on GET `/api/status` is true when no future NFP/CPI/FOMC falls within 35 days (`CALENDAR_STALE_WITHIN_MS`). The process logs `calendar stale` once per stale stretch. Web and iOS show that line when the flag is true.
- Checklist: freeze existed, knowledge_time after print, no market orders, kill/flatten clicked, paper bid/ask seen.

US cash holidays are orthogonal to GATE. GET `/api/status` exposes top-level `marketSession` (`cashOpen`, `inCashSession`, `closedReason` weekend/holiday/early_close, `holidayName`, `asOfEt`, `nextOpenEt`, `nextCloseEt`, `nextOpenAt`, `nextCloseAt`) from `shared/marketSession.ts`. Calendar is the standard NYSE equity holiday set in America/New_York (weekend observance; no external holiday API). `cashOpen` is a calendar-day flag (Mon–Fri, not a full holiday) — it does not mean “inside 09:30–16:00 RTH right now.” `inCashSession` is that inside-hours flag: 09:30 ET until the cash close (16:00 ET, 13:00 ET on early-close days). `nextOpenAt` / `nextCloseAt` are the ISO instants (display twins `nextOpenEt` / `nextCloseEt`). Web and iOS show a muted warning strip when closed (`US cash market closed — Labor Day` / `weekend`); early-close days are a secondary note. Desktop header, web `/m`, and the iOS Event Gate essentials header also show a compact countdown beside the ET clock: `Cash close in …` while `inCashSession`, otherwise `Cash open in …` until the next 09:30. Duration drops zero higher units (`2h 14m 03s`, `14m 03s`, `03s`). The second tick is local from those timestamps; it does not add a status poll. Early closes and holidays come from the server instants, not a client Mon–Fri 09:30–16:00 clock. Does not change GateMode, flatten books, or pause AUTO. Future: holiday FCM is not implemented. On iOS that countdown sits under the ET clock in the essentials header (`CashCountdownText`), using the same server instants via the Swift port of `cashCountdownTarget` / `formatCashCountdown` in `EssentialsFormat`.

## RISK ON / RISK OFF (badge)

Independent of the csp sleeve. Does not bind the day book, the csp book, the event clock, GATE, or flatten (server/src/risk.ts). Cached 15 minutes.
Exposed read-only and unauthenticated at GET /api/public/risk ({riskOn, riskChecks, asOf} only) so external watchers (e.g. Grok's risk-on/off routine) can poll it directly without Mac access or credentials — see Runtime.

RISK ON iff all of:

1. SPY last > 200-day SMA (spyAbove200)
2. ACWI last > 200-day SMA (acwiAbove200)
3. HYG last > 200-day SMA (hygAbove200)
4. UUP 20-session return is present and not greater than +3% (RISK_UUP_VETO_FRAC). Missing UUP 20d is a dollar veto.

Each of spyAbove200, acwiAbove200, and hygAbove200 is tri-state: true or false only when `featuresFromBars` computed it from real dailies, null when that series is missing or shorter than 200 sessions. `riskOn` stays fail-closed — true only when all three are strictly true and the dollar veto is clear — so a null check keeps the badge RISK OFF. Null is not "below 200dma". `riskOffFallback` (empty cache, a hard quotes failure, or a thrown gate) publishes those three as null and `dollarVeto` true. The public tooltip and the web/iOS why-line say "SPY 200dma missing" (same for ACWI and HYG), not "SPY below 200dma". A process-local staleness window, `RISK_ABOVE200_STALE_MAX_MISSES` (3, the same count as the overlay missing-bars debounce), repeats the last computed boolean for that check on the first two consecutive null refreshes and publishes null on the third. At the 15-minute risk cache that is about 45 minutes: a few refreshes, inside one cash session, not a full-session hold. The window is not persisted; a restart with bars still missing publishes null. Dollar veto is not carried — missing UUP still vetoes. Massive dailies.

When RISK OFF: no new momentum longs, no new options call-debit verticals; ownership pauses new adds only (existing longs stay unless their own exits fire). Risk-off sleeve expressions may run (see below).

## Paper engine

- MockBroker in Redis (mock:orders, mock:positions, mock:day_pnl). Independent $100k equity per sleeve (DEFAULT_SLEEVE_EQUITY_USD).
- Blotter + sleeve cards in Redis. Session marks (NY calendar date) split daily vs total P/L.
- Paper blotter (web, per sleeve): each open mock position row shows unrealized P/L (`uPnL`, position `unrealizedPnl`) and day P/L (`dPnL`, position `dayPnl`). uPnL is the delayed-last signed mark vs average (or vertical/overlay MTM already on the book). dPnL uses that same `signedPnl` (side, qty, point value) with prior close as the reference instead of average; if prior close is missing, the quote's day change is the point move. Debit verticals use E*TRADE `netChange` (long minus short) times the 100 multiplier; short overlays use the opposite sign of the leg's `netChange`. Dollars use the same sign and green/red as sleeve-tab P/L. dPnL is not MockBroker.getDayPnl() / `mock:day_pnl`. The paper mark writes `dayPnl` next to `unrealizedPnl`. Flat or zero qty is not an open row and does not show a P/L. Fill-history rows stay the journal (time, symbol, side, qty, price, notes) with no P/L columns. Display of the paper book only. Does not change live or E*TRADE order routing.
- Autopilot (AUTO_PAPER_INTERVAL_MS = 5 min) per sleeve. Five independent flags (`autoPaperBySleeve`: day, momentum, options, ownership, csp). Snapshot `autoPaper` is true if ANY sleeve is on (backward-compatible badge / old clients — not a sixth switch). Default all on when Redis has no key. The csp flag defaults ON when the key is absent, including a payload that still has a retired `riskoff` field. Explicit `csp: false` stays off. Legacy `0` is all off including csp; legacy `1` is all on including csp. The options-sleeve CSP/CC overlay is still manual. The csp sleeve itself sells cash-secured puts when its AUTO flag is on. Day sleeve auto-papers MES (stochastic + VWAP) only when `day` is on, GATE is idle, and Stage-3 is armed (NFP/CPI/FOMC ET day, stamp on that day at or after the anchor, now at or after the stamp). PRE-ARM / NO-STOP BAND / SESSION FLATTEN still veto new entries. Ordinary idle RTH without knowledge_time does not open MES. On a CPI day the same day AUTO flag also runs `cpiLateFade` when `CPI_LATE_FADE_ENABLED` is true (see day sleeve). RISK ON does not bind either day leg. Other sleeves as below.
- Redis `paper:auto` stores JSON `{ day, momentum, options, ownership, csp }`. A stored `riskoff` key is stripped on hydrate. Legacy global `0`/`1` migrates on first boot: `0` → all off, `1` → all on. Do not silently re-enable day into a print. After merge: GitHub Actions build + rsync (docs/DEPLOY.md); migration runs when the VPS process hydrates Redis.
- POST /api/paper/auto: `{ enabled }` sets ALL sleeves (old clients); `{ sleeveId, enabled }` sets one; `{ sleeves: { day: bool, … } }` batches. `{ sleeves }` wins, then `{ sleeveId, enabled }`, then `{ enabled }`.
- POST /api/paper/reset `{ sleeveId }`: MockBroker only. Wipes one sleeve to a clean $100k book without a delayed last or fill: drop that sleeve's mock positions, cancel its working orders, zero paper journal + blotter, align the session mark so daily and total P/L are 0. Then rebuilds mock:day_pnl so getDayPnl() equals the sum of remaining sleeves' session daily (stale cross-sleeve marks cannot keep tripping GATE daily-loss after leftover books are flat). Does not zero another sleeve's session daily out of dayPnl. Other sleeves, AUTO PAPER, and GATE stay as-is. Refuses when the broker is not MockBroker. Does not place a live or E*TRADE order. POST /api/paper/close still needs a delayed last (or vertical/overlay mark) and is the wrong ops path before cash prints. POST /api/flatten still only flattens gated day-sleeve names. POST `/api/day-pnl` still sets the accumulator by hand.
- Vertical guards (shared/constants.ts): no new verticals at/after 15:50 ET weekdays (OPTIONS_VERTICAL_CUTOFF_MINUTES); net debit at most half the width (OPTIONS_DEBIT_MAX_WIDTH_FRAC); same-underlying cooldown the rest of the ET day after a 50% debit stop (OPTIONS_DEBIT_STOP_FRAC). Target 30-45 DTE; exit at 21 DTE; profit take 50% of debit. Size near 1% of sleeve equity (OPTIONS_DEBIT_TARGET_FRAC), hard cap 2% (OPTIONS_DEBIT_CAP_FRAC). Multiplier 100.
- Stops on mock last. Last ≤ 0 is ignored (missing/junk prints must not flatten). One mark-to-market pass at a time so a stop cannot book twice. Paper only. That mark rule is unchanged.
- Status path (`snapshot()` for GET `/api/status` and the WS status snapshot) kicks `markPaperQuiet` in the background (`kickMarkPaperQuiet`) and returns the current book immediately — it does not wait on delayed Massive/Yahoo last or E*TRADE option chains for verticals/overlays. GET `/api/quotes` still awaits `markPaperQuiet` before responding. If a kicked mark flattens (`hits > 0`), it publishes a follow-up status snapshot. No change to GATE, AUTO PAPER, auth, EVENT_GATE_OPS_TOKEN scope, or the status JSON shape.
- Vertical exit fill price is the immediate close natural credit (long bid - short ask), the same number the position marks against; it is not close + entry debit (a 2026-09-03 bug briefly double-counted the debit, e.g. recording .27 instead of .07).

## Sleeve methodologies

Five sleeves (SLEEVE_IDS): day, momentum, options, ownership, csp. Each has its own mock book. The risk-off sleeve was deleted, including its history.

### 1. day — Day trading (events)

Horizon: intraday. Budget hint 15%. Loss cap $500 (day sleeve realized P/L, not mock:day_pnl).

Event-clock futures sleeve. Instruments on the quote strip: MES, ZN, M6E, SR3 (Massive Futures front-month lasts; Yahoo =F fallback). NFP/CPI/FOMC GATE still binds: PRE-ARM, NO-STOP BAND, and session flatten refuse new entries; flatten 15:45 ET (15:30 FOMC). Per-sleeve AUTO does not bypass GATE vetoes. Autopilot papers MES only when day AUTO is on and Stage-3 is armed: the America/New_York day has an NFP, CPI, or FOMC row, knowledge_time is stamped on that day at or after the anchor print, and `now` is at or after the stamp. A stamp on a non-print day, a stamp from before the print, ordinary idle RTH with no stamp, or a leftover stamp from another ET day does not open new MES stoch lots. The status field `stage3Armed` is that rule. Web recomputes it from `events`; iOS has no event list and reads the flag. The decision reason for a non-print stamp is `knowledge_time not on a print day`; a pre-print stamp is `knowledge_time before print`. PRE-ARM and NO-STOP BAND still veto new entries after the stamp. Existing open lots keep stop, VWAP-exit, 15:45 flatten, and sleeve loss cap. Signal: 5-minute slow stochastic 14,3,3, longs only above session VWAP, shorts only below, qty 1, stop at least 8 ticks or the signal bar. VWAP exit is two consecutive completed 5m closes on the wrong side of session VWAP (DAY_VWAP_EXIT_CLOSES = 2); a single-bar pierce holds. Day MES 5m bars prefer Massive Futures aggregates on the front-month contract from `GET /futures/v1/contracts` + `GET /futures/v1/aggs/{ticker}?resolution=5min` (not a synthetic F: ticker; Massive has no continuous REST symbol). Yahoo 5m MES=F is fallback only when Massive Futures is unconfigured or the response is unusable — the process logs which source won. Not E*TRADE. Paper symbol stays MES=F. RISK ON does not bind this book. MockBroker only.

CPI-day late-session fade (`cpiLateFade`, flag `CPI_LATE_FADE_ENABLED`, default on). Paper / MockBroker only. No live orders. It runs only when day AUTO is on, and only on an America/New_York day that has a CPI row in the same calendar the day sleeve already uses (`events` from Postgres `loadEvents`, otherwise `seedEvents()`). NFP, FOMC, claims, and PPI do not qualify. It does not hardcode dates. October 2026 CPI is present (`cpi-2026-10-14`, 08:30 ET, in `seedEvents()` and migration `005_calendar_through_2027.sql`). New entries also need Stage-3 (knowledge_time on that CPI day at or after the 08:30 anchor), GATE idle, qty 1, and the sleeve loss cap not already hit. PRE-ARM, NO-STOP BAND, and SESSION FLATTEN still refuse a new fade entry. RISK ON/OFF does not block it.

Reference price is MES 5-minute bars (Massive Futures front-month aggs, Yahoo `MES=F` fallback) — not a separate SPY feed. The stochastic leg reads only bars from the current ET date, so session VWAP stays one session. Its Massive aggs are still two UTC days back, oldest-first (`limit=1000`). The Yahoo fallback for that series and for the fade is `range=5d`, not `range=1d`. `range=1d` starts around 00:05 ET and has no prior cash close. `range=5d` includes the prior 16:00 ET bar (the 15:55 window start) across a weekend or a one-day NYSE holiday. The fade also merges a Massive fetch from five calendar days back, newest-first (`sort=window_start.desc`, `limit=1000`), so today's bars are not truncated. Front-month resolution passes `date` (the ET session), `active=true`, and `last_trade_date.gte` that date, then picks the nearest outright. After MESU6 stopped trading in September 2026 that contract is MESZ6. Bars are window-start labeled. The prior regular-session close is the close of the previous NYSE session's 15:55 ET bar (that bar ends at 16:00). Weekends and full NYSE holidays are skipped; an early-close session still uses the 15:55 bar. The 10:30 ET price is the close of today's 10:25 ET bar. Signal is the sign of 10:30 minus that prior close. At 15:30 ET (the autopilot pass in [15:30, 15:35)) enter 1 MES opposite that sign: first move up → short, down → long. A zero move, a missing 15:55 or 10:25 bar, or a series whose latest completed bar is more than 30 minutes old is no trade — never a default direction. A skip inside the 15:30–15:35 ET entry window is logged once per ET day at info (`[EventGate] cpiLateFade skip: …`) so journalctl shows why it did not enter. The working StopMarket is 0.4% adverse to the mock fill (`CPI_LATE_FADE_STOP_FRAC`). The existing paper note that a stop outside 1–2% is atypical still logs; it does not block this stop. A completed 5m close already 0.4% adverse to the fill average also flattens. Exit is flatten at or after 15:59 ET (cash close), including a later pass the same evening or the next session if the process was down. Never hold overnight. The sleeve loss cap flattens an open fade lot.

The lot is tagged `cpiLateFade` on the MockBroker position. Blotter notes/thesis start with `cpiLateFade`, so its P/L is separate from the stochastic thesis (`auto day MES stoch…`). If an untagged day MES (the stoch leg) is open at the entry pass, the fade skips. It does not net or double. The stochastic decision ignores a `cpiLateFade` lot, so VWAP-exit and the 15:45 flatten do not close it. Turning the flag off stops new entries; an open lot still flattens. Turning day AUTO off stops new entries; an open lot still flattens on the autopilot pass. This is a paper hypothesis (Yahoo SPY 60m, 2023-11-13 through 2026-10-09, FRED CPIAUCNS dates through 2026-04-10). It is not a tuned rule and not a proven edge.

### 2. momentum — Short-term momentum

Horizon: days-weeks. Budget hint 25%. Loss cap $1000. Auto cap MAX_AUTO_MOMENTUM = 5.

Universe: S&P 500 constituents (Massive dailies). Filter passesMomentumFilter (server/src/scan.ts): above 200dma, within 10% of 52-week high, last within -4% to +3% of 20dma (pullback-after-strength). Score: RS 3m vs SPY + 0.25 x RS 12m vs SPY + small volume bonus. Rank one name per GICS sector (top 15).

Entries (this sleeve AUTO on, RISK ON only): long the ranked names. Stop MOMENTUM_STOP_MUL = 0.985. Size about 1% sleeve equity at risk (AUTO_RISK_FRAC). Skip names already open on any sleeve.

Exits: sleeve loss cap; last below 200dma; setup gone (no longer in the momentum scan) when the scan is ready. RISK OFF: no new buys; existing stops/exits still run.

Quote-strip extras: MES, ES, SPY, QQQ, TLT (not auto-traded as a basket).

### 3. options — Options (defined risk)

Horizon: days-months. Budget hint 20%. Loss cap $1000. Auto cap MAX_AUTO_VERTICALS = 5.

Auto (this sleeve AUTO on, RISK ON only): ATM call debit verticals on momentum-scan names. Never puts, CSP, or covered calls from autopilot. Same 30-45 DTE / 15:50 cutoff / half-width debit / 50% stop machinery (pickAtmCallDebit). Thesis: auto call debit.

Manual: POST /api/paper/vertical (call or put) on this sleeve. POST /api/paper/csp and POST /api/paper/covered-call are ownership overlay booked on the options sleeve, tagged thesisSleeve=ownership or spcx. Never naked. Cash-secured put reserves strike x 100 x qty.

Quote strip: SPY, QQQ, IWM (live chains accept any ordinary US ticker).

### 4. ownership — Longer-term ownership + overlay

Horizon: months+. Budget hint 40%. Loss cap $2000. Auto cap MAX_AUTO_OWNERSHIP = 5.

Universe: same S&P scan. Filter passesOwnershipFilter: above 200dma and positive 3m/6m/12m returns (if 12m history is short, at least two of those legs). Rank by 12m return, max two names per sector (top 20). Skip isOwnershipArtifact (extreme 12m, stale 3m, more than 20% off highs, or last over $800) so autopilot does not buy one-off spikes.

Entries (this sleeve AUTO on, RISK ON only): long stock via that TA. Stop OWNERSHIP_STOP_MUL = 0.98. Size about 1% equity at risk.

Holds: RISK OFF pauses new adds only. Does not flatten the long-term book. Covered-call underlyers are not auto-sold. Exit if below 200dma or sleeve loss cap.

Overlay: CSP / covered call are manual, tagged to an ownership or SPCX thesis, sitting on the options sleeve. Autopilot does not sell puts or calls.

Quote-strip extras: SPY, QQQ, TLT, IWM.

### 5. csp — Cash-secured puts (oversold high-beta)

Horizon: days–months. Budget hint 100% of its own $100k paper book. Loss cap $10,000 (10% of the book; a $1,000 cap would flatten a short-premium book whose studied drawdown is larger). Status: paper. MockBroker only. Never a live order. E*TRADE is read-only chains and quotes. The options-sleeve CSP/CC overlay is a different feature and stays manual.

This sleeve is always eligible with respect to the risk regime. `riskOn`, the SPY/ACWI/HYG 200-day checks, and the UUP dollar veto do not gate entries or exits. It trades in both RISK ON and RISK OFF. Its gates are its own rules: the entry signal, earnings, liquidity (bid, open interest, spread), the no-leverage cash invariant, the 2× premium stop, cash-session hours, and E*TRADE chain availability. Global GATE OFF and the freeze modes (PRE-ARM, NO-STOP BAND, SESSION FLATTEN) block new shorts. AUTO for this sleeve (default ON) also blocks new shorts when off. Protective exits (2× stop, an earnings date that appears after entry, expiration) still run during the cash session when GATE is off or AUTO is off, so an open put is not abandoned.

Universe: current S&P 500 members that are single-name US common stocks on NYSE or Nasdaq (`shared/cspUniverse.ts`, refreshed 2026-10-17). No ETFs, ETNs, funds, ADRs, or OTC names. Duplicate share classes GOOG, FOX, and NWS are dropped. High beta: trailing 252-day beta to SPY above 1.3, recomputed about monthly and cached.

Signal, after the cash close, acted on the next session: slow stochastic (30,5,5) %K crosses up through %D while %K is below 20, and the MACD(12,26,9) histogram is up versus the prior day. There is no 200-day filter.

Earnings: skip the name when any earnings date falls on entry through expiration inclusive, or when the calendar is unknown. A date that appears after entry closes or rolls the put before that date.

Trade: sell one or more cash-secured puts. Expiry nearest 45 DTE inside 35–50. Strike nearest 0.20 delta, using E*TRADE greeks when present and Black-Scholes from chain IV otherwise (rate is the live 13-week yield when known, else 0.04). Sell fill is max(bid, mid − 0.25×spread). Skip when bid ≤ 0.05, open interest < 100, or the spread is wider than half the mid. Record bid, ask, mid, IV, delta, open interest, and volume.

No leverage: reserve strike×100×contracts. Reserved collateral plus the market value of assigned shares never exceeds sleeve equity. At most 10 concurrent puts, about 10% of equity of collateral each, whole contracts. Skip when one contract would be more than 15% of equity, and skip (and log) when a signal would break the cash rule. Idle cash and reserved collateral accrue T-bill yield in paper P/L when a rate is known.

Exit: buy back when the put mid reaches 2× the entry premium (checked on the autopilot pass, at least every 15 minutes, and at the close). Otherwise hold to expiration. OTM expires worthless. ITM (underlying close below the strike) is assigned at the strike from reserved collateral, then the shares are sold at the next session open. No wheel.

Shadow exits are log-only and never place or close an order. The same checks record the first trigger, the put mid and bid/ask, a buy fill of min(ask, mid + 0.25×spread), and P/L versus the actual close. Rules: tp50 (mid ≤ half the credit), dte21, combined (50% or 21 DTE or 2×, first), tp75, swing_low (close below the 20-session swing low before entry; close check only), spy_200 (SPY close below its 200-day average; close check only), probability take-profit `|delta| ≤ 0.05` and remaining mid ≤ 25% of credit, probability stop `|delta| ≥ 0.50`, and the combos `7+2x`, `8+2x`, `7+8+2x`. Variants: `7d03` (`|delta| ≤ 0.03` and mid ≤ 25% of credit), `8d40` (`|delta| ≥ 0.40`), and `7d03+2x`, `8d40+2x`, `7d03+8d40+2x`. Delta is the E*TRADE greek when present, otherwise Black-Scholes from chain IV. Summaries are on the csp status payload and the web book.

Option-chain recorder: after the close (16:15–16:25 ET) and mid-session (12:30–12:40 ET), snapshot put chains. `needs_pin` logs, sets the recorder blocking flag, and does not throw. The recorder runs even when csp AUTO is off. Postgres tables `csp_option_snapshots` and `csp_shadow_exits` are migration 006.

The live autopilot calls `runWiredCsp` on every mock tick, before the early return that skips other sleeves when every AUTO flag is off, and passes `riskOn` into `runCspDecisions` without branching on it. `planCspEntry` is the only new-short gate. That tick does not yet fill candidates from Massive bars or E*TRADE chains, and it does not yet write snapshot or shadow rows, so a running process does not open puts until those feeds are connected. The rules above are what the decision functions enforce. A test sells a put when `riskOn` is false.

The deleted risk-off sleeve (ETF relative-strength overlay, credit-leg put debits, gated duration, cash sweep, and its blotter, cards, marks, and Redis key `paper:riskoff_distributions`) is purged on boot: open paper lots are flattened in MockBroker with no live order, then the rows are deleted. The purge is idempotent and does not touch other sleeves or `GET /api/public/risk`.
